**Goal:** Prove sub-project 7's done table, rows 1–8:

**Spec:** `docs/superpowers/specs/2026-11-03-trenchline-shots-design.md`: "What done means", rows 1–8.

## Global Constraints

- **The baseline** (b702dd6, this Mac): 297 passed and 11 failed, all timing gates, while the machine was loaded: Spotlight at 85% CPU, and the battery draining on AC. Alone, `perf.spec:65` passed at 12.3–13.7 ms.
- **What row 8 asks:**
  - every test that passed at b702dd6 still passes;
  - the 11 timing gates are rerun one at a time on a quiet machine (load average under 3, battery not draining: `pmset -g batt`, `uptime`), and each passes or has its cause found.
- **The both-peaks gate:** `tests/e2e/peak.spec.ts` and `perf.spec.ts:391`. GPU p95 ≤ 14 ms, main-thread p99 ≤ 8 ms.
- **Pushing:** nothing is pushed or deployed here. Publishing is the user's word, which they gave for the end of the whole build. See memory `trenchline-sp7-shots-and-publish`.

## Review Focus

- **A perf gate that passes only alone:** report it with both runs' numbers, never as simply passing.
- **Captures taken at rest:** a capture that shows nothing happening (lights held, the front off) proves nothing. Each tool must run the battle and the shots it says.
- **The playtest page** must be the build under test (`npm run dev` on the `shots` branch), not the deployed site.
